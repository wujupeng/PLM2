# 测试假设与约束

1. 只访问 loopback 上的 `dev` 服务；创建数据前必须验证系统服务健康且数据库为 H2。不会连接生产、预发布或未知地址。
2. 组织名称、部门名称、人员姓名和岗位按测试任务书使用中文原文；每轮使用唯一编码/用户名后缀以支持重复运行。
3. 任务书示例密码不写入仓库。Provisioner 和测试账号密码通过本地环境变量注入；示例 JSON 只记录变量名。
4. 任务书没有提供角色到菜单/权限 ID 的矩阵。种子脚本只创建无权限角色，不向业务角色授予超出明示范围的权限；相关授权验收等待明确的角色权限基线。
5. 系统用户保存 DTO 不含岗位字段，岗位名称临时保存在备注以便识别；因此不宣称岗位主数据已经建成。
6. AF1000 主业务、业务数量/金额守恒及财务/数据迁移对账必须使用系统真实单据和流水；禁止用本地构造对象或 mock 结果判 PASS。
7. 未执行破坏性服务重启、数据清理、生产级攻击载荷或性能压测。H2 重启数据丢失以其内存型配置为已知限制。

## 第二轮补充

8. 用户确认 `http://localhost:3000/dashboard` 所在环境为专用隔离测试环境；因此只在本机 loopback 发起 P0 只读探测。
9. 第二轮允许目标严格列于 `test-data/allowed-hosts.json`；所有业务/启动测试脚本均先校验该清单。`.env.local` 当前不存在，本轮没有读取、打印或使用任何凭据。
10. A1 静态路径对照只产生候选匹配；没有将路径匹配、页面文件数或健康端点折算成业务成熟度。
11. Gateway 诊断时经用户授权启用了 loopback、禁用持久化的临时 Redis；记录健康变化后停止了两个明确 PID。冒烟测试在临时 Redis 活跃期间执行；最终没有 Redis 进程或持久化数据残留。
12. 第三轮开发将本地测试 Redis 改为带认证、启用 RDB/AOF 的 127.0.0.1:6381 专用实例。当前 Redis 已停止；其本地密码和配置只保留在 Git 忽略目录中，Gateway 的新配置尚未通过现有运行进程验证。

## 2026-11-20 AF1000 闭环推进决策

- **适用范围：** 仅本机隔离开发/测试环境，用于推动 AF1000 × 500 闭环；不是生产规则、报价或财务凭证。
- **决策来源：** 用户明确要求不再等待人工确认，按候选草案和建议继续，并完整记录假设。

### 开发环境与持久化

1. 运行中的内存 H2 数据由本地 bootstrap/seed 脚本重建；允许停服务并丢弃该内存实例，不再以保护这些数据为由阻塞重启。
2. 本机开发过渡使用 PostgreSQL 模式的文件 H2，文件放在 Git 忽略目录 `.local/dev-h2/`；需验证 system 重启后数据保留。该方案不是 D1-02 最终验收。
3. 目标测试机 PostgreSQL 使用独立 Docker Compose 与迁移验证脚本；本次发现开发机没有 Docker，Compose 文件存在不等于 PostgreSQL 迁移已通过。

### 权限矩阵 v1

1. 用户授权采用 [D0-business-rules-draft.md](./D0-business-rules-draft.md) 的岗位职责、禁止行为和组织范围作为本机权限矩阵 v1；不等于生产授权。
2. `admin_qk` 只做账号/组织/权限平台维护。`admin_max_*` 是隔离技术排障账号，只用于环境/权限/API 诊断，不可执行审批、库存、质量放行或职责分离/越权验收；测试结束删除。
3. 每个岗位仅授予其目标流程所需的模块/API权限；不授予 wildcard、全系统管理员或其他岗位权限。`guest_qk` 不授予业务权限。
4. 数据范围按草案：业务人员只限本人、组织、下级组织或分配业务对象。若应用未实现草案要求的记录级权限，则标记缺陷/阻塞，不用全权限账号代替。
5. 提交人不得审批自己发起的单据；若对应业务审批入口没有该拦截，先添加失败集成测试，再实现并审计记录拒绝。

### 登出令牌

- 本轮采用无状态 JWT 的既有行为：登出清理客户端令牌，不引入 Redis 黑名单；访问令牌在过期前仍可被服务端接受。Redis 黑名单及强制撤销作为独立安全增强，不作为 AF1000 闭环通过条件。
- 不在报告、提交或测试输出中记录任何密码、JWT 或本机密钥。

### 测试结束清理

- 通过系统用户 API 删除本轮 `admin_max_*` 管理员账号。
- 对真实业务单据不做数据库删除或伪造回滚；如需重置数据，使用隔离测试实例/经批准的系统业务冲销流程。
