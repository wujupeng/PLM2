## 缺陷与阻塞

1. **BOM 行新增接口返回 500**：接口复现两次，API 泛化错误没有提供根因。缺少行时后续验证、MRP 及所有依赖该 BOM 的闭环步骤均为 BLOCKED。详见[缺陷报告](./defects.md)。
2. **Gateway 与 system JWT 签名密钥不一致**：Gateway 登录成功不代表后续受保护请求可用。需在保留当前 H2 数据的前提下安排配置核对和维护窗口；本轮未重启 system 或 Gateway。
3. **岗位账号无业务权限**：业务角色候选矩阵仍待批准；不得用管理员身份冒充岗位审批，也未擅自授予权限。
4. **业务口径未确认**：价格/币种、审批规则等未补造；初始库存数量虽在任务书给出，但本轮未通过 WMS 业务单据初始化。

## 下一步建议

1. 保全当前 H2 实例与新增草稿数据；先定位 BOM 行新增的 system 异常堆栈并修复，再用受控 API 验证新增、读回、数量守恒及多级展开。
2. 定位运行中 system 日志里的 BOM 行新增异常堆栈并修复；使用专用管理员账号复测新增、读回、数量守恒及多级展开。
3. 核对运行中 system 与 Gateway 的 JWT 密钥注入来源；确认一致后复测经 Gateway 登录及受保护 API。
4. 请业务负责人批准岗位权限矩阵、销售价格/币种和审批口径；确认产品计量单位如何维护。岗位角色流程应改用各自最小权限账号，而不是最高权限账号。
5. 完成前置审批后，从真实销售订单开始按任务书顺序继续；前置失败时后续仍保持 BLOCKED。测试结束后删除本次新增的最高权限账号。
