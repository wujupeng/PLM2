- `test-data/org.json` 定义乾坤之境控股有限公司、11 个部门和任务书列出的 14 个测试身份（13 个岗位账号及 `guest_qk`）。

- 每轮使用唯一运行 ID 生成组织编码、角色编码和用户名，保留中文名称；成功后逐一通过系统登录接口验证账号。

## 执行结果

**BLOCKED — 没有创建任何数据。** 当前环境未配置本地 provisioner/test 密码环境变量，种子脚本在发出任何 HTTP 请求前以明确断言退出。网关 health 已可由启动脚本及临时 Redis 恢复，但没有 provisioner 权限凭据。没有尝试使用默认/猜测密码，没有直接修改数据库。

未满足的 S01 验收：公司/部门树在系统中真实创建、14 个用户及角色真实创建、各账号登录成功。准备隔离 dev H2 环境和本机秘密环境变量后，可通过任务书指定的接口创建流程重跑。

## 权限及字段假设

- 任务书未提供每个角色的细粒度权限矩阵，因此脚本创建角色时不授予任何权限，避免擅自给予广泛权限。该账号数据仅用于登录验证，未获得业务操作授权；权限/E2E 测试继续 BLOCKED。
- 当前 `UserSaveRequest` 没有独立岗位字段；岗位名称写入测试用户备注，不将备注误报为正式岗位字段。
- 测试账号使用本机环境变量提供的统一测试密码或逐账号环境变量。不得提交 `test-data/accounts.json` 或真实/可用密码。
